# TonUtils

## Facts
- **Name:** TonUtils
- **Domain:** tonutils.io (Cloudflare account `Leirapcom@gmail.com's Account`, id `2af090fc01e069acc0cf62dc60cce5d2`; zone id `1488cd4455682db22ea082e40374d7e3`)
- **Purpose:** A free toolbox for the TON blockchain. Regular users and developers find every tool they need, plus guides, curated links and featured ecosystem projects.
- **Type:** Website
- **Repo:** https://github.com/ugorur/tonutils (**public**)
- **Stack:** Nuxt 4, TypeScript, pnpm, deployed as a Cloudflare Worker (Nitro `cloudflare_module` preset). TON libraries: `@ton/core`, `@ton/crypto`, `@ton/ton`. TonConnect is used for actions that need a wallet signature.
- **Database:** none. Tools catalog, links and projects live as content files in the repo.
- **Login:** none (public)
- **Languages:** English only.

## Rules
- **The repo is public.** Never commit secrets, private keys, mnemonics, internal hostnames or customer data. Every file should be something we are fine with the world reading.
- **Tools run client-side.** Mnemonics, private keys and other sensitive input are processed in the browser and never sent to our server or logged. Each tool page says this.
- Read on-chain data from public APIs (toncenter, tonapi). Never put API keys in client code. If a key is needed, proxy the call through a server route and read the key from a Worker secret.
- Tools that send transactions go through TonConnect. The site never holds user keys.
- Links and projects must be real and verified. No placeholder URLs.

It reads `.nuxt/` as generated by the running dev server or the last `pnpm install`. `pnpm typecheck` (`nuxt typecheck`) regenerates `.nuxt/`: run it only when you are alone.
- **Per-tool tests**: `corepack pnpm vitest run app/tools/<slug>`.
- Before calling work done: `pnpm test`, `pnpm typecheck`, `pnpm build` all green.
- Heavy libraries (exact pinned versions, see `package.json`): `qrcode`, `jsqr`, `uplot`, `@ton/tasm`, `@ton-community/tlb-parser`, `@ton-community/tlb-runtime`, `@ton/tolk-js`, `@ton-community/func-js`, `@ton/sandbox`. `pnpm-workspace.yaml` overrides `@ton/core` to one version so `Cell`/`Address` from different libraries are the same class.
- Dev-only smoke page `/__dev/loaders` (`app/dev/LoaderCheck.vue`) runs every lazy loader for real in the browser (disassemble a mainnet wallet, sandbox `seqno` vs toncenter, Tolk/FunC hello world executed in the sandbox, TL-B decode, QR round trip, uPlot) plus a preview of the wallet components. Registered only by `nuxt dev`, or by a build with `TONUTILS_DEV_PAGES=1`.

## Adding a tool
Each tool is one self-contained folder. You never edit a central list: the registry finds tools with `import.meta.glob`, and `nuxt.config.ts` prerenders `/tools/<folder>` and adds it to the sitemap.

```
app/tools/<slug>/
  meta.ts        export default defineTool({...})   (import { defineTool } from '~/utils/tool')
  Tool.vue       the UI; rendered client-only inside <ToolShell> by app/pages/tools/[slug].vue
  logic.ts       pure TypeScript, no Vue; all real work happens here
  logic.test.ts  vitest tests for logic.ts with known-good vectors
  *.vue / *.ts   any extra files the tool needs (sub-components, a *.worker.ts), imported explicitly
```

- **meta.ts fields** (`ToolMeta` in `app/utils/tool.ts`): `slug` (must equal the folder name, kebab-case), `name` (sentence case), `short` (≤100 chars, cards/search), `description` (1–2 sentences, page + SEO), `category` (one id from `app/utils/categories.ts`; do not add categories casually), `audience: 'user' | 'dev' | 'both'`, `network: 'offline' | 'read' | 'wallet'`, `keywords: string[]`, optional `related: string[]` (existing slugs), optional `privacyNote` (replaces the network privacy line under the tool: set it when the browser also calls a non-TON API such as CoinGecko/STON.fi/DexScreener, or when the tool relays through `server/api/tools/*`), `icon` (literal `'i-lucide-*'` string so the icon bundler finds it; check the name exists in `@iconify-json/lucide`), optional `featured`.
- Categories: `address`, `wallet-keys`, `units-format`, `cells-boc`, `contracts`, `transactions`, `jettons`, `nfts`, `dns-domains`, `explorer-lookup`, `network-stats`, `crypto-encoding`, `developer-misc`, `security`, `wallet-actions` (send & sign through TonConnect), `token-launch` (create jettons/NFT collections, vesting), `staking`, `payments` (payment links, QR, checkout), `defi` (prices, DEX pools, swaps), `telegram` (usernames, numbers, Mini Apps), `reference` (exit codes, op codes, TVM, TEPs, cheat sheets).
- `app/utils/registry.test.ts` checks every meta.ts (slug = folder, valid category, icon prefix, related slugs exist). Keep it green.
- **Tool.vue** has no props. It may import `@ton/*` freely: it only ever runs in the browser. Pages and shared layout must not import `@ton/*` (SSR/prerender must stay crypto-free). Read the network with `useTonNetwork()` and default tabs to it.
- Components that import `@ton/core` (AddressInput, AddressLink, TxPreview) work only inside Tool.vue: `@ton/core` touches `Buffer` at import time, and Tool.vue is loaded after the Buffer plugin. Never use them in a page.
- **Never** send mnemonics/keys anywhere, never log them, never persist them. `network: 'read'` tools call public APIs from the browser through the composables below; if an API key is ever needed, proxy through a `server/` route that reads a Worker secret.
- **Coin naming.** Toncoin was renamed **Gram (GRAM)** on 2026-06-15. The chain is still TON (say "TON network", "TON address"), units are unchanged (1 GRAM = 10^9 nanoGRAM, formerly nanoTON). Never hardcode the coin symbol: use `COIN_SYMBOL`, `COIN_NAME`, `COIN_FORMER`, `NANO_NAME`, `NANO_FORMER`, `COIN_DECIMALS`, `COIN_RENAME_NOTE` and `formatCoin()` from `app/utils/currency.ts` (auto-imported). Mention "formerly Toncoin" / "nanoTON" in hints where users may search for the old name.
- **Test vectors must come from independent sources**: on-chain data (cite tx hash / address and the API you read it from), official docs and TEPs, or another library's test suite. Never paste values produced by our own code as the expected result.
- **Evidence**: exercise the UI in a real browser (playwright-cli) and save `/home/ugorur/Projects/Tektik/tonutils-evidence/tools/<slug>-desktop.png` (1280 wide) and `<slug>-mobile.png` (390 wide). A tool is not done until `corepack pnpm vitest run app/tools/<slug>` passes with real vectors, the parallel-safe typecheck is clean, and both screenshots exist.

### Wallet tools (`network: 'wallet'`)
- Wrap the whole interactive part in `<WalletGate purpose="send jettons">…</WalletGate>`. Its default slot renders only with a connected wallet on the site's network (slot prop `wallet`); otherwise it shows the connect CTA or a wrong-network warning.
- **Always render `<TxPreview :messages="messages" />`** with the exact messages you will send, before the send button. Never call `sendTransaction` with anything the user has not seen there.
- Send through `useTonConnect().sendTransaction({ messages, validUntil? })`. `validUntil` defaults to now + 5 min (unix seconds); keep it short. The site network is passed to the wallet; a mismatch throws `TonConnectNetworkError` with a readable message. Show errors with `<ErrorNotice :error>` (it maps wallet rejection `UserRejectsError` to "Rejected in wallet").
- After sending, call `waitForTransaction(result.hash)` and link the result with `<ExplorerLinks kind="tx" :value="trace.external_hash" />` (or show the address page). Test on testnet first (the header switch); never hardcode mainnet.
- Build bodies with `~/utils/ton/messages` builders, never by hand in Tool.vue. Default to bounceable destinations for contracts, non-bounceable for plain wallet transfers to uninitialized accounts.

Auto-imported composables:
- `useTonNetwork()` → `{ network: Ref<'mainnet'|'testnet'>, isTestnet, toggle }` (cookie-persisted; read it only client-side).
- `useToncenter(network?)` → `{ v2<T>(method, query?) /* returns result */, v3<T>(path, query?), post<T>(path, body) /* v3 POST, e.g. runGetMethod */, baseUrl() }`.
- `useTonapi(network?)` → `{ get<T>(path, query?), post<T>(path, body), baseUrl() }`.
  Both: keyless, one queue per host (~1 req/s), retry with backoff on 429/5xx/network errors, throw `TonApiError { provider, status, url, body, isRateLimit }`. Always use them (never raw `fetch` to toncenter/tonapi).
- `useTonConnect()` → `{ getUi(): Promise<TonConnectUI>, ui, wallet: Readonly<Ref<ConnectedAccount | null>>, connected, restored, networkMismatch, supportsSignMessage, connect(), disconnect(), sendTransaction({ messages: TonConnectMessage[], validUntil? }): Promise<{ boc, hash }>, signData(payload: SignDataPayload), signMessage({ messages, validUntil? }): Promise<{ internalBoc }>, waitForTransaction(bocOrHash, { timeoutMs = 120000, intervalMs = 4000 }?): Promise<TonTrace> }`.
  - `ConnectedAccount = { address /* 0:hex */, friendly /* UQ…/0Q… */, chain, network, publicKey?, walletStateInit, device, walletName, walletImage? }`.
  - `TonConnectMessage = { address: string /* EQ/UQ keeps its bounce flag; raw 0:… is sent bounceable */, amount: bigint | string /* nano */, payload?: Cell | string /* base64 BOC */, stateInit?: Cell | string }`.
  - `hash` is the TEP-467 normalized external-message hash (hex); `waitForTransaction` polls toncenter v3 `/traces?msg_hash=` until `trace_state === 'complete'` and returns the trace (`TonTrace`: `trace_id, external_hash, transactions, transactions_order, trace_info, …`).
  - Types: `import type { ConnectedAccount, TonConnectMessage, TonTrace } from '~/composables/useTonConnect'`.

### Server routes
- Tool-specific server routes live in `server/api/tools/<slug>/**` (served at `/api/tools/<slug>/…`) and nowhere else. Use them only for what a browser cannot do (e.g. a call that needs a Worker secret or has no CORS). There is no general API-key proxy, and none will be added: one route per concrete need, validate every input, never forward arbitrary URLs.

### Shared code between tools
- `app/lib/<group>/` holds code shared by a group of tools (e.g. `wallet-actions/` SendFlow, RecipientInput, `recipientNotes`; `accounts/`; `nfts-read/`). Change it with every importer in mind: grep for the folder before editing.
- Some tools import another tool's `logic.ts` (contract-deployer and library-publisher → stateinit-builder / unfreeze-account, dns-record-editor → adnl-address-converter, local-get-method-emulator → tvm-stack-codec, verify-signature → sign-message, metadata-validator → jetton-metadata-codec). Keep those exports stable or move them to `app/utils/ton/` when you change them.
- `server/api/tools/metadata-validator/fetch` (client side: `checkUrl` in `app/lib/jettons-dev/fetchCheck.ts`) is the site's one URL checker: public http(s) only, private hosts refused, redirects re-checked, JSON/SVG bodies only. metadata-validator, jetton-metadata-codec and tonconnect-link-decoder use it.

### Links and projects
- `app/data/links/<id>.ts` → `export default defineLinkCategory({...})`; `app/data/projects/<id>.ts` → `export default defineProjectCategory({...})` (types in `app/data/types.ts`). Auto-discovered, sorted by `order`. Verify every URL resolves before adding it.
